- 2026-08-12 — Built the loom→**Hermes** adapter (`adapters/hermes/`), loom's **third** adapter (Nous Research Hermes agent) and the first to **bind the macro project-management protocol to a resident daemon** (ADR-018 #8 deferred the daemon to an adapter). Added `wiki/environments/hermes.md`, the SETUP.md harness-table row, the SPEC "Hermes delivery conformance" section, and `validate_hermes_config` in `scripts/validate.sh`. **No ADR** — the adapter docs + this log entry record the approach (per the effort's direction). Macro-PM protocol unchanged (ADR-018 bound, not modified)

Wrote **ADR-019** (resident thin-macro adapter: renders only the `wayfinder-macro` profile, dispatches SDLC **down** into a separate per-invocation harness via prose; micro ledger = **shared, on-disk, gitignored** because memory can't cross a harness boundary; folds the ADR-018 "peer workflow" amendment). Reconciled the whole `adapters/hermes/` tree (`setup.md`, `MAPPING.md` §2–§3 now record the absence of stage/utility profiles, `STAGES.md` stub, all `references/*`, templates — dropped `stage.skill.md.template`), `SPEC.md`, `wiki/environments/hermes.md`, and applied **Option A** (micro ledger gitignored-by-default) to `wiki/adr/adr-014-loom-opencode-setup.md` + `wiki/patterns/seam-artifact-protocol.md`. Sharpened the macro-pm reactive state machine into an explicit **recursive tree-walk** (5 node kinds; `task`→buildable-leaf-dispatch or graduate-to-sub-map; `wayfinder:*` down / `sdlc:*` up; forest of concurrent root maps)

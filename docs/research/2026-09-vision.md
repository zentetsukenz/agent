# Research behind the 2026-09 vision restatement

Reviewed 2026-09-24 while restating [VISION.md](../../VISION.md). This page is **background, not
authority**: the vision does not depend on any source here, and nothing here amends it. Sources are
recorded so later work — above all the open "how" questions in round 2 — can start from them instead
of re-searching.

Claims marked *vendor-reported* or *relative* are not independently verified.

## Round 1 — context, human-in-the-loop, the human's role

| Source | Key point | Informs |
|---|---|---|
| Ryan Lopopolo, [*Harness engineering: leveraging Codex in an agent-first world*](https://openai.com/index/harness-engineering/) (OpenAI, Feb 2026) | A team of 3–7 engineers shipped ~1M lines with **zero** written by hand. "Humans steer. Agents execute." "Anything it can't access in-context while running effectively doesn't exist." AGENTS.md is a ~100-line map; the repository is the system of record. Admitted unknowns: long-run architectural coherence, and where human judgment compounds most. | "Humans keep the theory" (the no-human-code forcing function); "Knowledge lives in the project" |
| Birgitta Böckeler, [*Harness engineering for coding agent users*](https://martinfowler.com/articles/harness-engineering.html) (martinfowler.com, 2026-04-02) | "Agent = Model + Harness", with a **builder** harness (the vendor's) and an **outer** harness (the team's). Guides (feedforward) and sensors (feedback), each computational or inferential. "A good harness should not necessarily aim to fully eliminate human input, but to direct it to where our input is most important." Open problems: harness coherence as it grows; harness templates falling out of sync with upstream. | The industry definition of *harness* the vision adopts; "Autonomy is earned by checks" |
| Anthropic, [*Effective context engineering for AI agents*](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (2025) | Context is finite; aim for the smallest set of high-signal tokens. A tool set a human cannot disambiguate, an agent cannot either. | "the smallest set of true, current facts the task needs" |
| Zhang et al., [*Agentic Context Engineering (ACE)*](https://arxiv.org/abs/2510.04618) (arXiv 2510.04618, Oct 2025) | Evolving "playbook" contexts (generate → reflect → curate) let a *smaller* open model match the top-ranked production agent on AppWorld and beat it on the harder split; +10.6% on agent tasks. Names *brevity bias* and *context collapse*. *Relative*: "smaller" than the leaderboard model, not small. | "Written and checked beats smarter" |
| Belcak et al., [*Small Language Models are the Future of Agentic AI*](https://arxiv.org/abs/2506.02153) (NVIDIA, Jun 2025) | Position paper: SLMs suffice for most agent invocations; heterogeneous systems reserve a strong model for decide/plan moments. | The payoff of conviction 1: smaller, cheaper, more local models per task |
| 2026 open-weight coding models, e.g. [Morph's ranking](https://www.morphllm.com/best-open-source-coding-model-2026) | A dense ~27B model reported at ~77% SWE-bench Verified, near the late-2025 frontier. *Vendor-reported.* The deeper point: a benchmark **hands the model a well-formed issue**; a real project must produce that context itself. | "Why this is possible now" |
| Peter Naur, *Programming as Theory Building* (1985) — [summary](https://inventwithpython.com/drafts/naur-programming-as-theory-building.html) | The program is the theory in its builders' heads; code is a by-product; when the builders leave, the theory is lost. | "Humans keep the theory" |
| Lisanne Bainbridge, [*Ironies of Automation*](https://en.wikipedia.org/wiki/Ironies_of_Automation) (1983); [Friedrichsen, *AI and the ironies of automation*](https://www.ufried.com/blog/ironies_of_ai_1/) | Automation leaves humans the hardest residual tasks, erodes the skills those tasks need, and assigns monitoring — which humans sustain poorly. | Why keeping the theory is also what keeps a human able to judge |
| Feng, McDonald, Zhang, [*Levels of Autonomy for AI Agents*](https://arxiv.org/abs/2506.12469) (Jun 2025) | Five levels by the user's role: operator, collaborator, consultant, approver, observer. Autonomy is a design decision separate from capability. | "*Semi*-automated is the design" |
| Andrej Karpathy, [*Software 3.0*](https://www.latent.space/p/s3) (YC AI Startup School, Jun 2025) | Partial autonomy, the "autonomy slider", "Iron Man suit, not Iron Man robot". | "*Semi*-automated is the design" |
| Bitter-lesson critiques of harnesses, e.g. [Hugo Bowne-Anderson](https://hugobowne.substack.com/p/ai-agent-harness-3-principles-for), [MindStudio](https://www.mindstudio.ai/blog/ai-agent-harness-maintenance-models-improve) (2026) | Scaffolding that compensates for a weak model becomes a shackle as models improve; "a 2026 harness is a 2026 artifact". The strongest objection to the vision's premise. | "Scaffolding … is temporary by design; what the project knows and can check is not" |
| Agentic AI Foundation standards — [AGENTS.md and Agent Skills](https://dev.to/alexmercedcoder/open-standards-for-agentic-harnesses-5824) | AGENTS.md adopted by >60k projects; SKILL.md (open spec since Dec 2025) read by ~40 products. Portable instruction formats now exist across tools. | Why tool-independence moved from the vision's headline to its reason ("Knowledge lives in the project") |
| METR, [2025 RCT](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/) and [2026 design change](https://metr.org/blog/2026-02-24-uplift-update/) | Early-2025 AI made experienced developers 19% slower while they believed they were 20% faster; the 2026 follow-up could not recruit a no-AI control group. | Caution: the vision makes no productivity claim |
| [DORA 2025, *State of AI-assisted Software Development*](https://dora.dev/dora-report-2025/) | "AI is an amplifier" of an organisation's existing strengths and weaknesses; its capability model includes AI-accessible internal data. | "Why this is possible now" — the gap is the project, not the model |

## Round 2 — build vs customize; resident vs ephemeral

Open input for the "how" session. **Nothing here is decided** — the vision names two shapes (a
resident agent that never stops, ephemeral agents that start fresh per piece of work) and is neutral
on whether Jacquard builds or customizes the harness that realizes them.

| Source | Key point | Bearing on the open question |
|---|---|---|
| DeepSeek Harness (`dsh`) — [project page](https://deepseek.com/harness/en/), [repository](https://github.com/deepseek-ai/deepseek-harness), [InfoQ](https://www.infoq.com/news/2026/08/deep-seek-harness/) (Aug 2026, MIT, **developer preview**, "compatibility-breaking changes") | "Agent = Model + Harness"; *everything is a plugin* on the Cordis kernel — models, tools, skills, sessions, sandboxes, storage, **loops, scheduling**, UI. Interactive and scheduled/long-running use. Append-only session log of everything the model sees. Prefix-cache discipline claimed to cut unit cost 1–2 orders of magnitude (*vendor-reported*). No stated support for AGENTS.md or SKILL.md. | One base might host **both** shapes. Blurs build vs customize: building becomes composing plugins. Cache discipline is a second cost lever beside small models. |
| [Hermes Agent](https://github.com/nousresearch/hermes-agent) (Nous Research, Feb 2026) | Resident: messaging gateway, built-in cron, persistent memory, self-written and self-improving skills. | The resident shape, already an adapter target. Its self-curated memory is in tension with "knowledge lives in the project". |
| Claude Agent SDK — [overview](https://www.morphllm.com/claude-agent-sdk) | Drive Claude Code's harness programmatically: permission modes, callbacks, unattended runs. | "Build" today mostly means composing on a proven vendor loop, not writing one. |
| Anthropic, [*Effective harnesses for long-running agents*](https://anthropic.com/engineering/effective-harnesses-for-long-running-agents) (Nov 2025) | An initializer agent sets up a feature list and progress log; each session reads git and the progress file, does one feature, leaves artifacts for the next. | Written state is what spans sessions — convergent with "a fresh agent anywhere can rebuild the whole picture". |
| Ambient-agent literature, e.g. [Broda](https://agenticmesh.substack.com/p/ambient-agents), [Tian Pan](https://tianpan.co/blog/2026-04-17-ambient-ai-architecture-always-on-agents) (2026) | Pull-based session agents vs event-driven daemons with persistent identity, service-account execution, least privilege, and survival across interruption. | The resident/ephemeral split, with the security posture each needs. |

## Naming

Jacquard was chosen on 2026-09-24. The Jacquard loom (1804) moved the pattern from the weaver's head
onto punched cards the machine read, while a weaver still worked the loom — the vision in one
machine — and is an ancestor of programmable computing.

Rejected because live projects already hold the name in this space: **Centaur**
([paradigmxyz/centaur](https://github.com/paradigmxyz/centaur), agent infrastructure),
**Yoke** ([rp-exp/yoke](https://github.com/rp-exp/yoke), drives coding-agent harnesses),
**Heddle** ([getheddle/heddle](https://github.com/getheddle/heddle), multi-LLM orchestration),
**Bottega** ([vdaubry/bottega](https://github.com/vdaubry/bottega), always-on coding-agent
orchestration). Also taken: Warp, Mise, Crew, Rudder, Helm/Tiller, Forge, Smithy.

These were web and GitHub searches, **not a trademark search**. Check trademark registers, the GitHub
organisation, and npm/PyPI before the repository-wide rename.

## OKF

The wiki's frontmatter convention is Google Cloud's **Open Knowledge Format** — the
[specification](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) is
at **v0.2**. Differences from how this repository currently describes it, for the OKF pass:

- The repository's SPEC names it "Open Knowledge *Framework* v0.1".
- OKF `type` values are **not** a fixed list ("not registered centrally"; producers SHOULD pick
  descriptive values). The repository's closed list is a local restriction.
- OKF makes `index.md` and `log.md` **optional**; the repository requires both per subtree.
- v0.2 adds optional `resource`, `sources`, `generated`/`verified`, and `status`/`stale_after`.
- OKF consumers must tolerate broken links; the repository's gate deliberately does not.

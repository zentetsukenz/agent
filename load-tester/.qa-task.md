## QA Scope

### Phase 1: Pre-Assessment
- [ ] Verify project structure and dependencies
- [ ] Check configuration files (ESLint, Prettier, Vite, etc.)
- [ ] Review package.json for outdated/vulnerable dependencies
- [ ] Verify git status (uncommitted changes, untracked files)

### Phase 2: Static Analysis
- [ ] **Linting**: Run ESLint on frontend code
- [ ] **Formatting**: Check Prettier compliance
- [ ] **Type Safety**: Verify prop-types or TypeScript usage
- [ ] **Code Quality**: Check for code smells, complexity, duplication
- [ ] **Import Analysis**: Verify proper module imports and tree-shaking

### Phase 3: Security Assessment
- [ ] **Dependency Vulnerabilities**: Run `npm audit` for both workspaces
- [ ] **Secret Detection**: Scan for hardcoded credentials, API keys, tokens
- [ ] **OWASP Compliance**: Check for common vulnerabilities
  - SQL Injection (Prisma queries)
  - XSS vulnerabilities (React components)
  - Authentication/Authorization issues
  - CORS configuration
  - Input validation
- [ ] **Environment Variables**: Verify .env files not committed, proper handling

### Phase 4: Testing & Coverage
- [ ] **Backend Tests**: Run `npm run backend:test`
  - Unit test results
  - Integration test results
  - Coverage percentage (target: ≥80%)
  - Test quality assessment
- [ ] **Frontend Tests**: Run `npm run frontend:test`
  - Component test results
  - Coverage percentage (target: ≥70%)
  - Test quality assessment
- [ ] **Test Reliability**: Check for flaky tests
- [ ] **Edge Cases**: Verify error handling and boundary conditions

### Phase 5: Performance Analysis
- [ ] **Frontend Bundle Size**: Check Vite build output
- [ ] **Component Performance**: React rendering optimization
- [ ] **API Response Times**: Analyze backend endpoint performance
- [ ] **Database Queries**: Check for N+1 problems, unoptimized queries
- [ ] **Memory Leaks**: Look for potential memory leak patterns

### Phase 6: Code Quality Review
- [ ] **Architecture**: Assess component structure, separation of concerns
- [ ] **Code Readability**: Naming conventions, comments, documentation
- [ ] **Error Handling**: Try-catch blocks, error boundaries, validation
- [ ] **Best Practices**: React hooks usage, async/await patterns
- [ ] **Technical Debt**: Identify TODOs, FIXMEs, deprecated patterns
- [ ] **Maintainability Index**: Overall code maintainability score

### Phase 7: Accessibility (Frontend)
- [ ] **WCAG 2.2 Compliance**: Check accessibility standards
- [ ] **Semantic HTML**: Proper HTML5 elements
- [ ] **ARIA Attributes**: Screen reader support
- [ ] **Keyboard Navigation**: Tab order, focus management
- [ ] **Color Contrast**: Verify contrast ratios for text/backgrounds
- [ ] **Alt Text**: Images have descriptive alt attributes

### Phase 8: Build & Deployment Readiness
- [ ] **Frontend Build**: Run `npm run frontend:build` successfully
- [ ] **Backend Start**: Verify `npm run backend:start` works
- [ ] **Environment Configuration**: Production-ready configs
- [ ] **Database Migrations**: Prisma migrations applied correctly
- [ ] **Health Checks**: Verify health check endpoints exist
- [ ] **Monitoring Setup**: Check if logging/monitoring is configured

## Success Criteria

### Must Fix Before Deployment (Blockers)
- **CRITICAL (🔴)**: No critical security vulnerabilities
- **CRITICAL (🔴)**: No system crashes or data corruption risks
- **CRITICAL (🔴)**: All critical path tests passing
- **HIGH (🟠)**: No high-severity security vulnerabilities in new code
- **HIGH (🟠)**: Build must complete successfully

### Quality Thresholds
- Backend test coverage: ≥ 80%
- Frontend test coverage: ≥ 70%
- Code duplication: < 5%
- Cyclomatic complexity: ≤ 10 per function
- Zero linting errors (warnings acceptable)
- npm audit: Zero critical/high vulnerabilities

### Nice to Have
- MEDIUM (🟡): Performance optimizations
- LOW (🟢): Minor usability improvements
- TRIVIAL (⚪): Code style, formatting consistency
